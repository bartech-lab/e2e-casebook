# Case 8: magic-link sign-in

## Feature

The **Account** page takes an email and sends a sign-in link. Mail never leaves the app: each
sandbox has a test inbox on the **Mail** page and at `GET /api/s/:id/mail`. The link signs you in
once, expires after 10 minutes, and sets a session cookie scoped to the sandbox. **Sign out** ends
the session.

What can go wrong: a link works twice; mail is never sent; the account page ignores a valid
session.

## Approaches

| # | Spec | What it does |
|---|---|---|
| 1 | [`1-ui-inbox`](1-ui-inbox.spec.ts) | The whole journey in the page: request, open the Mail page, click the link, sign out, reuse the link. |
| 2 | [`2-mail-api`](2-mail-api.spec.ts) | Requests in the page, reads the link from the mail API, opens it. |
| 3 | [`3-login-hook`](3-login-hook.spec.ts) | `POST /__test__/s/:id/login` returns a session cookie; no mail at all. |
| 4 | [`4-storage-state`](4-storage-state.spec.ts) | Signs in once through the API in `beforeAll`, saves `storageState`, and reuses it in three tests. |

`storageState` keeps cookies and localStorage, not sessionStorage, so approach 4 answers the
name prompt again in every test.

## Trade-offs

- **1 UI inbox.** The only approach that tests the link's rules, because only it tries the link a
  second time. It is the longest, and it needs an inbox the test can reach; a real mail provider
  would need a mail-testing service.
- **2 Mail API.** Shorter, and still proves mail is sent and the link works. It skips the inbox
  page and checks only the happy path.
- **3 Login hook.** The fastest way to a signed-in state, and blind to the whole sign-in flow. It
  is the right setup for tests about something else that need a signed-in user.
- **4 Storage state.** Pays for sign-in once per file. The saved state goes stale when sessions
  expire, and it depends on where the app keeps what, as the sessionStorage name prompt shows.

Test the sign-in flow itself once, end to end with its negative path (1). Every other test signs
in through the hook (3) or saved state (4).
