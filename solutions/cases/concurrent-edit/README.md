# Case 2: concurrent edit

## Feature

The card editor loads a card with its `version`. Save sends `PATCH` with `If-Match: "<version>"`.
If someone saved in between, the server answers `412` with the current card; the page shows who
changed it and offers **Use theirs** (load their version into the form) or **Keep mine** (save my
text on top of their version).

What can go wrong: the server ignores `If-Match` and the later save silently wins, Keep mine
resends the old version and conflicts forever, Use theirs leaves my stale text in the form, or the
client never sends `If-Match` at all.

## Approaches

| # | Spec | What it does |
|---|---|---|
| 1 | [`1-two-contexts`](1-two-contexts.spec.ts) | Alice and Bob edit the same card in two browser contexts. |
| 2 | [`2-api-as-other-editor`](2-api-as-other-editor.spec.ts) | One page; the competing edit is an API call. |
| 3 | [`3-mocked-412`](3-mocked-412.spec.ts) | `page.route` answers the first save with a crafted `412`; checks the retry's `If-Match`. |
| 4 | [`4-api-contract`](4-api-contract.spec.ts) | No browser: stale and current `If-Match` through the API. |
| 5 | [`5-model-based`](5-model-based.spec.ts) | One page as Bob, Alice through the API. fast-check generates 60 random interleavings of typing, saving, Alice's saves, Keep mine, and Use theirs (fixed seed) and checks the form, the conflict panel, and the server title and version against a model of `If-Match` after every step. |

## Trade-offs

- **1 Two contexts.** The only approach that caught all four, because it is the only one that
  walks both buttons. It needs two browser contexts and about twice the time of 2 or 3.
- **2 API as the other editor.** Half the cost of 1 and still talks to the real server, so it
  proves the server's check and the client's retry. It misses whatever path it does not walk:
  here, Use theirs.
- **3 Mocked 412.** Can stage any conflict (a version far ahead, a third user) without timing
  tricks, and checks the exact header the client sends. It cannot see the server: a server that
  never returns 412 passes.
- **4 API contract.** Milliseconds, and the sharpest check of the server rule, but it says nothing
  about the page.
- **5 Model-based.** Catches all four. At 15 generated runs it missed "Use theirs keeps my
  draft": counting the generated steps showed that no sequence reached Use theirs during a
  conflict (0 of 15; 4 at 60 runs). Count the interesting events a seed produces
  (`fc.statistics` does this) before trusting a random test's misses.

A cheap pair that covers all four: 2 plus a second test in 2 for Use theirs, or 1 alone.
