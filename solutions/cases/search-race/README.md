# Case 38: search (debounce and out-of-order responses)

## Feature

The Search page sends `GET /api/s/:id/search?q=` 300 ms after the last key. Each search cancels
the one before it (`AbortController`) and ignores a response that arrives after a newer search
started. The status line names the text the shown results belong to, not the text in the box.

## What makes it hard

- **The race needs two requests in flight.** `fill()` sends one input event, and a fast local
  server answers before the next one. Without slowing the older response down, results always
  arrive in order.
- **Checking that something did not happen.** After the slow response lands, the test must wait
  until the page has had its chance to apply it. Waiting for `requestfinished` or `requestfailed`
  ends at a known event, not after a timeout.
- **Debounce is about time, and real time is slow and loose.** `page.clock` makes 299 ms and
  300 ms two distinct, instant steps.
- **Two texts look the same once the page settles.** The typed text and the searched text only
  differ during the debounce window.

## Approaches

| # | Spec | What it does |
|---|---|---|
| 1 | [`1-type-and-wait`](1-type-and-wait.spec.ts) | `fill()` and wait for results, for plain, `&`, no-match and empty text. |
| 2 | [`2-route-holds-stale`](2-route-holds-stale.spec.ts) | `page.route` holds the response for `la` until `lamp` has rendered, then releases it and checks nothing changed. |
| 3 | [`3-clock-debounce`](3-clock-debounce.spec.ts) | `page.clock.install()`, types key by key, counts requests at 299 and 300 ms, and checks the status during the next debounce. |

## Trade-offs

- **1 Type and wait.** Covers what the search returns. It cannot see order or timing.
- **2 Route holds stale.** The only way here to force responses out of order. It needs the
  release-and-settle dance, and it says nothing about how many requests were sent.
- **3 Clock.** Exact about debounce and the in-between state. It controls timers, not the
  network, so it never reorders responses.

A race is tested by making it happen on purpose, then waiting for an event that proves it is
over.
